# R85 — 三項效能改善

延續 R84，來源提交 `03fe3dc09b36477269ee2459747b300445fe1c5d`。版本為 `v5.0.0-dev.2-R85`，沿用同一個 Sites 專案與開發分支。

## 問題與改善

1. **收合內容仍先產生完整 HTML。** R84 每次進入或更新投資頁，都先產生全部其他投資收入、月份卡片及操作按鈕，即使收入區塊仍收合；每個金額也重建數字格式設定。R85 保留摘要金額，只在展開或進入「股息與收入」時產生明細，重用數字格式器。展開後保留新增、編輯、刪除、匯出、語言與無障礙處理；同分頁更新保持展開並使用最新資料。
2. **配息候選逐檔掃描全部交易。** R84 每檔股票分別尋找買入／期初交易，查詢分組又逐檔過濾相同代號。R85 一次掃描交易建立候選集合、一次掃描候選建立代號分組，並重用當次候選清單。跨帳戶同代號仍只查一次，再分別合併至各帳戶；不保存跨次候選快取，避免資料變更後過期。
3. **翻譯規則重複建立與匹配。** R84 中文啟動仍建立英文片語規則，每次文字處理都重建保護文字的正規表示式，重複標籤也重新比對。R85 延後至需要英文片語翻譯時才建立規則，重用保護規則，並以最多 512 筆的短文字快取重用結果。保護標記內的使用者文字不進入翻譯快取，大段文字不保留。

## 可重現的程式量測

原生 Node 執行既有函式，使用虛構資料；預熱兩次、取九次樣本的中位數。不是瀏覽器量測、整站啟動秒數、手機效能或 FPS。

| 測試案例 | R84 | R85 |
| --- | ---: | ---: |
| 1,000 筆收入、區塊收合：投資頁動態 HTML | 320,942 bytes | 7,122 bytes |
| 同案例：收入明細產生次數 | 1 | 0 |
| 同案例：產生頁面 HTML 中位時間 | 26.535 ms | 0.664 ms |
| 收入已展開：產生頁面 HTML 中位時間 | 25.144 ms | 7.415 ms |
| 200 檔／10,000 筆交易：讀取交易代號次數 | 1,980,100 | 200 |
| 同案例：配息候選篩選中位時間 | 35.543 ms | 0.193 ms |
| 中文啟動：英文片語規則編譯 | 1 次 | 0 次 |
| 同一英文動態標籤 1,000 次：片語比對 | 1,000 次 | 1 次 |
| 同案例：翻譯中位時間 | 8.023 ms | 0.219 ms |

上述 HTML 差異是動態頁面內容，不是下載檔案大小；交易仍完整走訪一遍，200 次是其中買入／期初交易的代號讀取次數。時間會隨執行環境變動。

完整輸出為 `R85-PERFORMANCE-RESULTS.json`。將 R84 的 app.js、stocks.js、stocks-ui.js、i18n.js、i18n-en.js 放在同一資料夾後，可執行：

```sh
node scripts/r85-performance-check.mjs /absolute/path/to/R84
```

## 相容性與程式驗證

- R84 與 R85 的完整收入 HTML、原始資料相同。
- 2,579 個翻譯輸入 × 三種語言偏好結果一致。
- 新增六項原生效能／功能檢查與一項跨帳戶配息合併檢查；含既有股票、行情、快取、背景及動畫回歸共 77/77 PASS。
- 保留 R84 的捲動位置、配息取消及恢復、窄螢幕持股配置。
- 保留 FIFO、薪資計算、資料 KEY `salarymate_v5_full_state`、Schema 15、備份與使用者自己的 Google Drive 流程。
- 背景、風格、晶羽飛行、攻擊姿勢與十種風系魔法素材不變；正式 v4.3.2 維持凍結。
- 不使用虛擬瀏覽器。手機與桌面實際展開觀感、操作延遲及動畫流暢度仍待實機驗證。
